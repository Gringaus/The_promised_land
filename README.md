# Земли основателя (Founder's Lands)

Реалистичная экономическая градостроительная стратегия на Unity 6 (HDRP).
Полная концепция игры — в `docs/ECONOMIC_STRATEGY_CONCEPT_RU.md` (GDD). Этот файл
описывает **техническую реализацию** и текущее состояние кода.

> Кратко: Manor Lords (деревня и логистика) × Foundation (органическое строительство)
> × Civilization (долгая стратегическая дуга) × Ancient Cities (выживание общины) —
> в виде 3D-стратегии сверху с процедурно меняющейся картой.

---

## Ключевое архитектурное решение: Simulation ↔ Presentation

Игра делится на два слоя с **односторонней зависимостью**:

| Слой | Что это | Зависит от Unity? | Где живёт |
| --- | --- | --- | --- |
| **Simulation** («мозг») | Генерация карты, ресурсы, логистика, жители, демография, сезоны, экономика, производство, земледелие, торговля, технологии, заготовки, разбойники, сохранения. Чистый C#, детерминированный от seed. | **Нет** (`noEngineReferences`) | `Assets/_Project/Scripts/Simulation/` |
| **Presentation** («вид») | MonoBehaviour, HDRP-материалы и шейдеры, Cinemachine-камера, UI, ScriptableObject-обёртки. | Да | `Assets/_Project/Scripts/Presentation/` и др. |

Зачем так (см. GDD §4, §26):

- самую сложную и баг-опасную логику (экономика, логистика на сотни агентов) можно
  **компилировать и юнит-тестировать без Unity и без GPU** — в CI или в песочнице;
- рендер/HDRP заменяемы и не мешают отлаживать «правила игры»;
- ScriptableObject в Unity — это **обёртки для авторинга данных** (data-driven, §20):
  они хранят поля и собирают чистые C#-структуры, которые потребляет симуляция. Баланс
  лежит в данных, а не в коде классов.

`FoundersLands.Simulation.asmdef` собран с `"noEngineReferences": true` — это
**технически запрещает** симуляции тянуть `UnityEngine`, то есть граница слоёв
проверяется компилятором, а не на словах.

## Что уже реализовано

### Модуль 1 — фундамент и генерация карты

- [x] Структура проекта по GDD §20 и разделение Simulation/Presentation через asmdef.
- [x] Детерминированный RNG (SplitMix64) и платформо-стабильный хэш (FNV-1a) —
      основа воспроизводимости карты по seed (§7, §21).
- [x] Детерминированная **послойная генерация карты** (§7): высота (fBm + контраст +
      островной спад) → климат → гидрология → реки → плодородие → биомы → ресурсы.
- [x] 8 биомов, 9 типов ресурсных залежей, модель тайла с почвой и влажностью.

### Модуль 2 — экономическая петля выживания (§9, §11, §28)

- [x] Ресурсы с качеством (data-driven каталог), питательность/тепло, спойл еды (§8, §12).
- [x] Склад с вместимостью и детерминированным потреблением.
- [x] Жители с потребностями: еда, тепло, здоровье, смерть; возрастная уязвимость (§11).
- [x] Сезоны и календарь: зима — главный стратегический риск (§9).
- [x] Добыча (фуражиры/дровосеки), привязанная к богатству долины вокруг участка.
- [x] Дневная симуляция: добыча → спойл → справедливое нормирование → здоровье → смерть.
- [x] Консольный прогон «доживём ли до весны» с посезонной сводкой и вердиктом.

### Модуль 3 — строительство и здания (§10)

- [x] Чертёж → этапы (фундамент → каркас → стены → крыша → ввод); стройка **замирает без материалов**.
- [x] Data-driven каталог зданий: стоимость в материалах, объём работ, эффекты.
- [x] Профессии лесоруб (древесина), каменотёс (камень), строитель; материалы берутся со склада.
- [x] Эффекты зданий: дома → жильё/тепло (меньше дров зимой), склад → вместимость, мастерские → бонус к добыче.
- [x] Аддитивная интеграция: при нуле зданий поведение Модуля 2 не меняется (баланс выживания сохранён).
- [x] Консольный прогон стройки `--mode build` с посезонной сводкой.

### Модуль 4 — сохранение и загрузка (§21)

- [x] Версионированный текстовый формат **без внешних зависимостей** (Unity-совместимо).
- [x] Сейв хранит seed + настройки генерации → карта восстанавливается ре-генерацией (опора на детерминизм).
- [x] Полное состояние: жители, склад, здания и стадии, часы, факторы, баланс-конфиг, состояние RNG.
- [x] Round-trip: `StateHash` сейва и загрузки совпадают; продолжение остаётся синхронным.
- [x] Консольный прогон `--mode saveload` (запись в файл, чтение, сверка хэшей).

> На этом **headless-MVP «мозга» собран целиком**: карта → ресурсы/жители/сезоны/выживание →
> строительство → сохранение, всё детерминированно и под тестами (см. §28).

### Модуль 5 — логистика и живые дороги (§7, §12)

- [x] A* по тайлам с ценой движения (вода непроходима, склон/болото/снег — дороже).
- [x] Живая дорожная сеть (runtime-маска): трафик протаптывает тропы → дороги, неиспользуемые тропы зарастают.
- [x] Перенос грузов между складами/зданиями; ходки штампуют трафик на маршрут.
- [x] Поле расстояний (Дейкстра) + opt-in: фактор добычи по реальной цене пути (по умолчанию выкл — баланс прежних модулей цел).
- [x] Консольный прогон `--mode logistics`: маршрут протаптывается, стоимость падает ~−65%.

### Модуль 6 — производство и рынок (§12)

- [x] Data-driven рецепты и мастерские: лес→доски (лесопилка), руда→слиток→инструменты (плавильня, кузница).
- [x] Профессии горняк (руда) и ремесленник; мастерская простаивает без сырья (как стройка без материалов).
- [x] Инструменты ускоряют все работы; рынок при наличии еды снижает бытовые издержки (бонус к выработке).
- [x] Аддитивно: без мастерских/инструментов/рынка множитель = 1 → баланс Модулей 2–5 цел.
- [x] Консольный прогон `--mode production`: колония 40 чел. живёт 4 года, доски и инструменты копятся по цепочкам.

### Модуль 7 — разбойники и угрозы (AI Director, §13)

- [x] AI Director: давление растёт от богатства и силы лагеря, падает от обороны; лестница эскалации
  слухи→разведчики→кражи→засада→рейд.
- [x] Последствия по стадиям: кражи ценностей, ранения в засаде, рейд (грабёж, урон здоровью, снос
  постройки). Провиант лишь подъедают — налётчики берут добычу, а не вырезают голодом.
- [x] Оборона: профессия дружинник, башня и частокол; удерживает давление и смягчает удар.
- [x] Броски угрозы бесстековые (хеш seed+день) → детерминизм и переживают save/load без курсора RNG.
- [x] Аддитивно: флаг `EnableThreats` выключен по умолчанию → Модули 2–6 не тронуты.
- [x] Консольный прогон `--mode raiders`: открытая колония терпит набеги и беднеет, защищённая (дружина+башни)
  спокойна и процветает.

### Модуль 8 — земледелие и поля (§9)

- [x] Сезонный цикл поля: сев весной, рост летом, жатва осенью → зерно, зимой под паром.
- [x] Уход решает урожай: труд земледельцев делится на поля; ухоженное плодородное поле вызревает полностью,
  заброшенное — частично.
- [x] Цепочка зерно→мука→хлеб (мельница + пекарня на движке Модуля 6; выпечка жжёт дрова). Хлеб куда сытнее зерна.
- [x] Аддитивно: без полей/земледельцев система простаивает → Модули 2–7 не тронуты.
- [x] Консольный прогон `--mode farming`: колония кормится с полей — осенью всплеск зерна, хлеб держит её зиму.

### Модуль 9 — демография и рост (§11)

- [x] Старение по годам, смертность по старости, рождения (нужны и сытость, и свободное жильё), миграция.
- [x] Дети не работают до 16 и едят меньше; повзрослев, занимают самую нужную профессию (баланс рабочей силы).
- [x] Рост ограничен пищевой ёмкостью и жильём (упреждающе, без перелёта в голод); рождения/миграция — детерминированные
  накопители, смерть по старости — бесстоковый бросок → переживает save/load.
- [x] Аддитивно: флаг `EnablePopulationDynamics` выключен по умолчанию → Модули 2–8 не тронуты.
- [x] Консольный прогон `--mode demography`: 16 поселенцев за поколение вырастают до устойчивого плато на потолке жилья.

### Модуль 11 — торговля и контракты (§12)

- [x] Караваны навещают колонию с рынком по расписанию: продают излишки сверх резерва и докупают
  до целевого запаса (продажа раньше покупки — экспорт финансирует импорт).
- [x] Цены от сезона (еда дороже в голодные месяцы) и безопасности пути; полуфабрикаты/инструменты
  дороже сырья. Базовые цены — в `ResourceDef` (data-driven).
- [x] Связь с угрозами (М7): опасная дорога рискует засадой — караван перехвачен, визит потерян.
- [x] Детерминизм: расписание по дню, бросок засады — бесстоковый хеш; серебро и тальи в save/load.
- [x] Аддитивно: флаг `EnableTrade` выключен по умолчанию → колонии с рынком из М6/М7 не тронуты.
- [x] Консольный прогон `--mode trade`: лесопильный городок экспортирует доски за серебро и
  ввозит инструменты, которых не куёт сам.

### Модуль 12 — технологии и прогрессия (§16)

- [x] Дерево технологий: учёные копят очки, техи открываются по порядку при выполненных пререквизитах.
- [x] Каждый тех открывает здания и/или даёт прибавку к выработке; стартовые здания (палатка/дом/склад)
  доступны без исследований. Строительство закрытого здания не проходит, пока тех не изучен.
- [x] Детерминизм: накопитель по фиксированному дереву; очки и изученные техи в save/load (открытые
  здания восстанавливаются до загрузки построек).
- [x] Аддитивно: флаг `EnableTechnology` выключен по умолчанию → все здания доступны как в Модулях 2–11.
- [x] Консольный прогон `--mode tech`: за поколение колония изучает дерево (Woodcraft→…→Engineering),
  открывает 11 зданий и набирает +30% к выработке.

### Модуль 14 — большой интегральный сценарий (все системы разом)

- [x] Одна колония со всеми подсистемами одновременно: земледелие + производство + торговля + угрозы +
  демография + технологии, прогон на десятилетия. Основатели приносят базовые техи, учёные доисследуют
  остальное; оборона держит угрозу, торговля копит серебро, население растёт.
- [x] Интеграционный тест-капстоун доказывает, что модули стыкуются, и служит холистическим стражем
  регрессий. Он же вскрыл и починил три латентных бага: недетерминированная сумма `TotalUnits`
  (порядок словаря → дрейф флоатов) и несохранение `SoilFertility` и `TradePolicy` в save/load.
- [x] Консольный прогон `--mode grand`: за 25 лет городок 40→~45 жителей, угроза Calm и 0 рейдов,
  ~36000 серебра, технологии 8/8 (+30% к выработке), здоровье 100.

### Модуль 16 — хранение и заготовки (§8)

- [x] Постройки-хранилища замедляют порчу скоропортящейся еды: погреб (−40%) и коптильня (−30%),
  складываются с убывающей отдачей и потолком (порчу не убрать полностью). Открываются технологией
  Agriculture; фактор пересчитывается из зданий (в save/load восстанавливается, не хешируется).
- [x] `Inventory.ApplySpoilage` теперь возвращает объём испорченного; колония копит `TotalSpoiled`.
- [x] Аддитивно: без построек фактор 0 → порча как раньше (М2–15 не тронуты).
- [x] Консольный прогон `--mode preserve`: две одинаковые колонии, у второй погреб+коптильня (−58%)
  — за 3 года спасено ~950 единиц еды от порчи, зимний запас вчетверо больше.

**Итого: 131 проходящий юнит-тест** по всему ядру (карта, экономика, выживание, строительство,
сохранение, пути/логистика, производство, угрозы, земледелие, демография, торговля, технологии,
хранение/заготовки, и сквозной интеграционный прогон).

### Модуль 17 — первый играбельный билд: `--mode play` (§28)

Первая **играбельная** сборка: живой цикл колонии, которым вы управляете простыми командами.
Запускается прямо сейчас (без Unity/GPU) — это headless-«игра» поверх ядра.

- [x] Реальное время с паузой/скоростью; команды: `step/season/year`, `build <тип> [x y]`,
  `labor <профессия> <0..1>`, `speed`, `save`, `load`, `status`, `help`, `quit`.
- [x] Живой дашборд: сезон/день/год, население/здоровье/жильё, еда (на сколько дней)/дрова, склады,
  стройки, серебро, расклад труда, лента событий (рождения/смерти/миграция).
- [x] Цель — вырастить колонию до 30; поражение — вымирание. Стартовый посёлок уже стоит
  (дома/склад/избы сборщиков); дефолтная колония выживает и растёт до потолка жилья (25) сама,
  а до победы её доводит активная игра: перебросить труд на стройку, поднять дома, вернуть еду.
- [x] `PopulationSystem.ReassignWorkforce` — мгновенно перераспределяет рабочих по текущим долям
  (рычаг команды `labor`). Два входа: живая клавиатура в терминале **или** скрипт команд
  (`--commands "...";` или из stdin) — для воспроизводимых прогонов, демо и тестов.
- [x] Собирается в автономный бинарь: `dotnet publish console -c Release -r <RID> --self-contained`.

> Это headless-играбельность (терминал). Играбельный **GUI**-вид — это `ColonyMapView` (Модуль 15),
> он требует Unity Editor и здесь не собирается; запускать его — у вас в редакторе.

### Модуль 10 — Unity-слой (каркас «вида», §14, §15, §20)

- [x] ScriptableObject-обёртки для авторинга (`WorldGenSettingsAsset`, `SettlementConfigAsset`):
  правят данные в Инспекторе → строят plain-C# записи ядра. Правила остаются в симуляции.
- [x] `ColonyHost` (MonoBehaviour) — мост: по seed генерирует мир и колонию и тикает
  `SettlementSimulation` в такт реальному времени (дней/сек), хранит текущее состояние для «вида».
- [x] `WorldMapTextureBuilder` — рисует карту в `Texture2D` (биомы, рельеф тенью, метки ресурсов).
- [x] `ColonyDebugOverlay` — IMGUI-оверлей: карта + живая сводка (сезон, население, еда/дрова, товары,
  здания, угроза/демография) + управление паузой/скоростью. Работает в любом пайплайне, без сцены.
- [x] Тот же seed (`green-valley`) даёт в Editor ту же карту, что и headless-CLI. Запуск — см.
  `Assets/_Project/Scripts/Presentation/README.md`.

> Этот слой компилируется только в Unity (нужен `UnityEngine`); ядро и его 120 тестов остаются
> headless. Дальше по «виду» (требуют GPU/редактор): HDRP-рендер и шейдеры (§18),
> UI Toolkit вместо отладочного IMGUI (§22), импорт ассетов (§19).

### Модуль 15 — интерактивный вид: камера, выбор, строительство (§14, §18, §10)

- [x] `ColonyMapView` — интерактивный IMGUI-вид над `ColonyHost`: панорама (drag средней/правой
  кнопкой или стрелки) и зум колесом к курсору, без сцены/префабов.
- [x] Выбор тайла кликом → панель деталей (биом, рельеф, плодородие, ресурс, здание и стадия стройки).
- [x] Режим строительства: палитра типов зданий с учётом тех-гейтинга (закрытые серые), клик по тайлу
  ставит чертёж через `Settlement.PlaceBlueprint` — дальше его возводят строители колонии.
- [x] Здания на карте маркерами (янтарь — в стройке, синий — готово), метка центра, призрак под курсором.

> Unity-код я не компилирую в headless-среде — проверять в Editor. Каркас следует конвенциям
> рабочего `ColonyDebugOverlay` (тот же IMGUI/стиль/построитель текстуры).

### Примеры вывода

Генерация карты (Модуль 1):

```
seed=17658872636640814876  size=100x50  seaLevel=0.32  contentHash=0x97E69BB11C7DCF58

Resources: Fish 154 · Wood 152 · Herbs 76 · Clay 68 · Berries 67 · Stone 41 · IronOre 14 ...
```

Прогон выживания (Модуль 2): богатая долина живёт годами, а каменистый участок без леса
замерзает без дров уже в первую весну — карта реально определяет экономику (§3):

```
Year Season   Pop    Food  Firewd    Nutr  Health  Died
   0 Autumn    20    1329    1427    1037   100.0     0
   0 Winter    20     398     596     310   100.0     0    <- запас тает зимой
   1 Summer    20    1138    1297     888   100.0     0    <- восстановление летом
Verdict: first winter SURVIVED (20/20 alive after winter of year 0)
```

Строительство (Модуль 3): за лето колония возводит все 8 зданий, не голодая; жильё на 25
снижает зимний расход дров, склад поднимает вместимость 6000 → 8500:

```
Year Season   Pop   Food  Firewd   Wood  Stone  Built  WIP    Cap  House
   0 Spring    28     69      86    114    103      5    3   8500     20    <- стройка идёт
   0 Summer    28   1213     933    370    247      8    0   8500     25    <- все 8 готовы
```

## Сборка и тесты (headless, без Unity)

Нужен только .NET SDK 8.0+.

```bash
cd SimHarness
dotnet test tests/FoundersLands.Simulation.Tests.csproj -c Release                       # все юнит-тесты
dotnet run --project console -c Release -- --mode map --seed green-valley                # карта (§7)
dotnet run --project console -c Release -- --mode survive --seed green-valley --years 5  # выживание (§9, §28)
dotnet run --project console -c Release -- --mode build --seed green-valley --years 4    # стройка (§10)
```

**Непрерывная интеграция.** GitHub Actions (`.github/workflows/ci.yml`) на каждый push/PR
собирает ядро и гоняет все 117 тестов плюс несколько headless-сценариев — Unity-слою
лицензия и редактор не нужны, в этом и смысл разделения Simulation/Presentation.
Качество гейтится сборкой без предупреждений (0 warnings) и тестами.

**Claude Code на вебе.** SessionStart-хук (`.claude/hooks/session-start.sh`) в веб-сессиях
заранее восстанавливает и собирает харнесс, чтобы тесты и CLI шли сразу, без ожидания.

## Открытие в Unity

1. Поставить **Unity 6.3 LTS** (или актуальную Unity 6 LTS-ветку, GDD §4).
2. Открыть папку репозитория как проект. Unity сам создаст `ProjectSettings/`,
   `Library/` и сгенерирует `.meta`-файлы при первом импорте — после этого их нужно
   закоммитить (в Unity-проектах `.meta` хранятся в git).
3. `Packages/manifest.json` задаёт целевой набор пакетов (HDRP, Cinemachine, Input
   System, AI Navigation, Burst/Collections/Mathematics, Addressables, Test Framework).
   **Версии пакетов** подобраны под Unity 6 и могут потребовать уточнения в Package
   Manager под вашу конкретную сборку 6.3 LTS.
