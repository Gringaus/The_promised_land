# Земли основателя (Founder's Lands)

Реалистичная экономическая градостроительная стратегия на Unity 6 (HDRP).
Полная концепция игры — в `docs/ECONOMIC_STRATEGY_CONCEPT_RU.md` (GDD). Этот файл
описывает **техническую реализацию** и текущее состояние кода.

> Кратко: Manor Lords (деревня и логистика) × Foundation (органическое строительство)
> × Civilization (долгая стратегическая дуга) × Ancient Cities (выживание общины) —
> в виде 3D-стратегии сверху с процедурно меняющейся картой.

---

## Ключевое архитектурное решение: Simulation ↔ Presentation

Игра делится на два слоя с **односторонней зависимостью**:

| Слой | Что это | Зависит от Unity? | Где живёт |
| --- | --- | --- | --- |
| **Simulation** («мозг») | Генерация карты, ресурсы, логистика, жители, сезоны, экономика, разбойники, сохранения. Чистый C#, детерминированный от seed. | **Нет** (`noEngineReferences`) | `Assets/_Project/Scripts/Simulation/` |
| **Presentation** («вид») | MonoBehaviour, HDRP-материалы и шейдеры, Cinemachine-камера, UI, ScriptableObject-обёртки. | Да | `Assets/_Project/Scripts/Presentation/` и др. |

Зачем так (см. GDD §4, §26):

- самую сложную и баг-опасную логику (экономика, логистика на сотни агентов) можно
  **компилировать и юнит-тестировать без Unity и без GPU** — в CI или в песочнице;
- рендер/HDRP заменяемы и не мешают отлаживать «правила игры»;
- ScriptableObject в Unity — это **обёртки для авторинга данных** (data-driven, §20):
  они хранят поля и собирают чистые C#-структуры, которые потребляет симуляция. Баланс
  лежит в данных, а не в коде классов.

`FoundersLands.Simulation.asmdef` собран с `"noEngineReferences": true` — это
**технически запрещает** симуляции тянуть `UnityEngine`, то есть граница слоёв
проверяется компилятором, а не на словах.

## Что уже реализовано

### Модуль 1 — фундамент и генерация карты

- [x] Структура проекта по GDD §20 и разделение Simulation/Presentation через asmdef.
- [x] Детерминированный RNG (SplitMix64) и платформо-стабильный хэш (FNV-1a) —
      основа воспроизводимости карты по seed (§7, §21).
- [x] Детерминированная **послойная генерация карты** (§7): высота (fBm + контраст +
      островной спад) → климат → гидрология → реки → плодородие → биомы → ресурсы.
- [x] 8 биомов, 9 типов ресурсных залежей, модель тайла с почвой и влажностью.

### Модуль 2 — экономическая петля выживания (§9, §11, §28)

- [x] Ресурсы с качеством (data-driven каталог), питательность/тепло, спойл еды (§8, §12).
- [x] Склад с вместимостью и детерминированным потреблением.
- [x] Жители с потребностями: еда, тепло, здоровье, смерть; возрастная уязвимость (§11).
- [x] Сезоны и календарь: зима — главный стратегический риск (§9).
- [x] Добыча (фуражиры/дровосеки), привязанная к богатству долины вокруг участка.
- [x] Дневная симуляция: добыча → спойл → справедливое нормирование → здоровье → смерть.
- [x] Консольный прогон «доживём ли до весны» с посезонной сводкой и вердиктом.

### Модуль 3 — строительство и здания (§10)

- [x] Чертёж → этапы (фундамент → каркас → стены → крыша → ввод); стройка **замирает без материалов**.
- [x] Data-driven каталог зданий: стоимость в материалах, объём работ, эффекты.
- [x] Профессии лесоруб (древесина), каменотёс (камень), строитель; материалы берутся со склада.
- [x] Эффекты зданий: дома → жильё/тепло (меньше дров зимой), склад → вместимость, мастерские → бонус к добыче.
- [x] Аддитивная интеграция: при нуле зданий поведение Модуля 2 не меняется (баланс выживания сохранён).
- [x] Консольный прогон стройки `--mode build` с посезонной сводкой.

### Модуль 4 — сохранение и загрузка (§21)

- [x] Версионированный текстовый формат **без внешних зависимостей** (Unity-совместимо).
- [x] Сейв хранит seed + настройки генерации → карта восстанавливается ре-генерацией (опора на детерминизм).
- [x] Полное состояние: жители, склад, здания и стадии, часы, факторы, баланс-конфиг, состояние RNG.
- [x] Round-trip: `StateHash` сейва и загрузки совпадают; продолжение остаётся синхронным.
- [x] Консольный прогон `--mode saveload` (запись в файл, чтение, сверка хэшей).

> На этом **headless-MVP «мозга» собран целиком**: карта → ресурсы/жители/сезоны/выживание →
> строительство → сохранение, всё детерминированно и под тестами (см. §28).

### Модуль 5 — логистика и живые дороги (§7, §12)

- [x] A* по тайлам с ценой движения (вода непроходима, склон/болото/снег — дороже).
- [x] Живая дорожная сеть (runtime-маска): трафик протаптывает тропы → дороги, неиспользуемые тропы зарастают.
- [x] Перенос грузов между складами/зданиями; ходки штампуют трафик на маршрут.
- [x] Поле расстояний (Дейкстра) + opt-in: фактор добычи по реальной цене пути (по умолчанию выкл — баланс прежних модулей цел).
- [x] Консольный прогон `--mode logistics`: маршрут протаптывается, стоимость падает ~−65%.

**Итого: 72 проходящих юнит-теста** по всему ядру (карта, экономика, выживание, строительство,
сохранение, пути и логистика).

Что **намеренно отложено** до работы в Unity Editor (нужен GPU/редактор):
рендеринг HDRP, шейдеры (§18), камера (§14), UI (§22), импорт ассетов (§19).

## Сборка и тесты (headless, без Unity)

Нужен только .NET SDK 8.0+.

```bash
cd SimHarness
dotnet test tests/FoundersLands.Simulation.Tests.csproj -c Release                       # все юнит-тесты
dotnet run --project console -c Release -- --mode map --seed green-valley                # карта (§7)
dotnet run --project console -c Release -- --mode survive --seed green-valley --years 5  # выживание (§9, §28)
dotnet run --project console -c Release -- --mode build --seed green-valley --years 4    # стройка (§10)
dotnet run --project console -c Release -- --mode saveload --seed green-valley           # сейв/загрузка (§21)
dotnet run --project console -c Release -- --mode logistics --seed green-valley           # пути и дороги (§7, §12)
```

Подробнее — `SimHarness/README.md`.

## Открытие в Unity

1. Поставить **Unity 6.3 LTS** (или актуальную Unity 6 LTS-ветку, GDD §4).
2. Открыть папку репозитория как проект. Unity сам создаст `ProjectSettings/`,
   `Library/` и сгенерирует `.meta`-файлы при первом импорте — после этого их нужно
   закоммитить (в Unity-проектах `.meta` хранятся в git).
3. `Packages/manifest.json` задаёт целевой набор пакетов (HDRP, Cinemachine, Input
   System, AI Navigation, Burst/Collections/Mathematics, Addressables, Test Framework).
   **Версии пакетов** подобраны под Unity 6 и могут потребовать уточнения в Package
   Manager под вашу конкретную сборку 6.3 LTS.

## Структура репозитория

```text
Assets/_Project/
  Scripts/
    Simulation/      # ← чистый C#, движок-независимый, тестируется headless
      Core/          #   RNG, стабильный хэш
      Mathematics/   #   координаты, шум, математика
      World/         #   биомы, ресурсы, тайл, генератор карты
      Economy/       #   ресурсы, качество, каталог, склад
      Time/          #   сезоны, календарь, часы симуляции
      Population/    #   жители, профессии, потребности
      Construction/  #   здания, этапы стройки, система строительства
      Pathfinding/   #   A*, поле расстояний, цена движения, дорожная сеть
      Logistics/     #   перенос грузов, носильщики
      SaveLoad/      #   сериализация состояния (seed + поселение)
      Settlements/   #   состояние поселения, дневная симуляция, фабрика колонии
    Presentation/    # ← Unity-слой (MonoBehaviour/HDRP/UI), добавляется в Editor
    Core/ Economy/ Construction/ Terrain/ AI/ UI/ SaveLoad/ Rendering/ Shaders/
  ScriptableObjects/ # data-driven определения (Buildings, Resources, Recipes, ...)
  Art/ Audio/ Materials/ Shaders/ Prefabs/ Scenes/ UI/ VFX/
Packages/manifest.json
SimHarness/          # headless-проекты для сборки/тестов симуляции (вне Assets/)
docs/                # GDD и проектная документация
```

## Дорожная карта (по GDD §24)

| Этап | Содержание | Статус |
| --- | --- | --- |
| Фундамент | Scaffold, Simulation/Presentation, генерация карты, тесты | **готово** |
| MVP (§24.1) | Ресурсы ✓ · жители ✓ · склады ✓ · сезоны ✓ · выживание ✓ · строительство ✓ · сохранение ✓ (headless) | **ядро готово** |
| Глубина (§25 «Потом») | Логистика и живые дороги ✓ · производство/торговля/разбойники — далее | **в работе** |
| Presentation | Unity-слой: камера, HDRP, шейдеры, UI, миникарта (нужен Editor/GPU) | далее у вас |
| Вертикальный срез (§24.2) | HDRP, погода, поля, цепочки, рынок, первые разбойники | — |
| Alpha / Beta / EA | по GDD §24.3–24.5 | — |

Принцип (§25, §28): сначала рабочая экономическая петля в числах, потом контент и
красота. Если базовая петля скучна — чиним её, а не добавляем здания.
